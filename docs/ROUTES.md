# مسیرهای پروژه

این جدول از فایل‌های `page.tsx` و `route.ts` موجود تهیه شده است. `[id]` و `[slug]` پارامترهای مسیر هستند. محافظت صفحه از `src/proxy.ts` می‌آید؛ تأیید نهایی مجوز عملیات بر عهده بک‌اند است.

## صفحات عمومی و حساب کاربری

| URL | کاربرد | دسترسی |
| --- | --- | --- |
| `/` | خانه، معرفی، دسته‌ها، دعوت به ثبت، مراحل و FAQ | عمومی |
| `/businesses` | مرور، جستجو، فیلتر و صفحه‌بندی کسب‌وکار | عمومی |
| `/businesses/[slug]` | مشخصات عمومی، نقشه، رسانه، خدمات، محصولات و نظرات | عمومی؛ عملیات تعاملی نیازمند ورود |
| `/login` | ورود/ثبت‌نام با OTP | عمومی |
| `/complete-profile` | تکمیل اطلاعات حساب تازه یا ناقص | نشست معتبر |
| `/dashboard` | کارت کاربر، وضعیت کسب‌وکار و منوی امکانات | نشست معتبر |
| `/dashboard/profile` | ویرایش حساب | نشست معتبر |
| `/dashboard/favorites` | علاقه‌مندی‌ها | نشست معتبر |
| `/dashboard/notifications` | اعلان‌ها و علامت‌گذاری خوانده‌شده | نشست معتبر |
| `/dashboard/business/new` | ثبت اولیه و ادامه ثبت موجود | نشست معتبر |
| `/dashboard/business/documents` | ارسال مجدد مدارک | نشست معتبر و کسب‌وکار موجود |
| `/dashboard/business/profile` | ادامه مرحله ذخیره‌شده یا فهرست ویرایش | نشست، مدارک کامل طبق منطق کد و وضعیت `APPROVED` |

## زیرصفحات پروفایل کسب‌وکار

همه مسیرهای زیر زیرمجموعه `/dashboard/business/profile` و مشمول layout آن هستند.

| پسوند | کاربرد |
| --- | --- |
| `/basic` | نام، بیوگرافی، لوگو و دسته‌بندی |
| `/contact` | شماره‌های تماس و واتساپ |
| `/features` | امکانات |
| `/address` | آدرس اصلی، مختصات و شعب |
| `/gallery` | تصاویر و ویدیوی معرفی |
| `/social` | شبکه‌های اجتماعی |
| `/services` | خدمات |
| `/products` | دسته محصول و محصولات |
| `/about` | متن درباره ما |
| `/hours` | ساعات کاری هفته |
| `/installment` | شرایط اقساط |

در جریان onboarding فعال، ورود به مرحله جلوتر از پیشرفت ذخیره‌شده در Context به مرحله فعلی برگردانده می‌شود. این محدودیت UI جای کنترل سمت بک‌اند را نمی‌گیرد.

## پنل مدیریت

| URL | کاربرد |
| --- | --- |
| `/admin/login` | ورود مدیر با شماره و رمز؛ استثنای عمومی proxy |
| `/admin` | شمارنده‌های کسب‌وکار و مدارک در انتظار |
| `/admin/businesses` | فهرست کسب‌وکارها |
| `/admin/businesses/pending` | کسب‌وکارهای در انتظار بررسی |
| `/admin/businesses/rejected` | فهرست ردشده‌ها با فیلتر محلی |
| `/admin/businesses/new` | ثبت دستی کسب‌وکار |
| `/admin/businesses/[id]` | مشخصات کامل، امکانات، رسانه، شعب، خدمات/محصولات، ساعات/اقساط، مدارک و کنترل پلن؛ خطای پلن صفحه را ۴۰۴ نمی‌کند |
| `/admin/categories` | مدیریت دسته‌بندی‌ها |
| `/admin/users` | فهرست و جستجوی کاربران |
| `/admin/users/[id]` | جزئیات، تعلیق و بازگردانی کاربر |
| `/admin/reviews` | مدیریت نظرات |

صفحات پنل به `ADMIN` یا `SUPER_ADMIN` نیاز دارند؛ نقش نامعتبر در proxy به `/dashboard` هدایت می‌شود. sidebar اکنون به صفحه نظرات لینک دارد؛ گزینه‌های بدون صفحه غیرفعال‌اند.

## Route Handlerهای داخلی

| URL | متدها | رفتار |
| --- | --- | --- |
| `/api/backend/[...path]` | GET، POST، PATCH، PUT، DELETE | افزودن `/api/` به مسیر بک‌اند، انتقال query/body و Authorization |
| `/api/auth/silent-refresh` | GET | refresh و هدایت به مقصد داخلی یا login |
| `/api/auth/silent-refresh` | POST | handshake JSON، بررسی/تمدید نشست برای mutation |

matcher در proxy مسیرهای API، `_next` و مسیرهای دارای نقطه را کنار می‌گذارد. API داخلی باید مجوز را از بک‌اند بگیرد؛ محافظت صفحات شامل این handlerها نمی‌شود.

## queryهای فهرست عمومی

`/businesses` پارامترهای `search`، `categoryId`، `city`، `neighborhood`، `vipOnly`، `hasMedia` و `page` را دریافت می‌کند و با `limit=20` به بک‌اند می‌فرستد. انتخابگر محله در UI فعلاً فقط گزینه خالی دارد و dropdown دوم شهر غیرفعال است؛ ورودی متنی شهر فعال است.

## مقصدهای قدیمی و رفتار اصلاح‌شده

| محل | رفتار فعلی |
| --- | --- |
| خانه | دسته‌ها به /businesses، ثبت به /dashboard/business/new، FAQ و معرفی به /#faq و /#about |
| مقالات، تماس و قوانین | غیرفعال با به‌زودی؛ صفحه ساختگی ایجاد نشده |
| VIP، پرداخت و پشتیبانی داشبورد | غیرفعال با به‌زودی |
| کیف پول، RBAC، پلن‌ها و پیام مدیر | غیرفعال با به‌زودی؛ نظرات فعال |
| nav-config | فقط مسیرهای موجود داشبورد، پروفایل کسب‌وکار، حساب، علاقه‌مندی و اعلان |

robots.txt و sitemap.xml از metadata routeها اضافه شده‌اند؛ sitemap بدون SITE_URL فهرست خالی دارد و با آن، دو ورودی عمومی خانه و businesses را معرفی می‌کند.

## جداسازی صفحات مدیر و کاربر

دسترسی نشست در جدول صفحات حساب، برای نقش‌های غیرمدیر است: `ADMIN` و `SUPER_ADMIN` از همه مسیرهای `/dashboard/**` و `/complete-profile` به پنل اصلی `/admin` هدایت می‌شوند. مدیر با نشست معتبر از `/login` و `/admin/login` نیز به `/admin` می‌رود. صفحات عمومی قابل مرور هستند؛ لینک حساب در هدر و منوی موبایل مدیر، `/admin` و لینک ثبت کسب‌وکار، `/admin/businesses/new` است. [رفتار و آزمون‌ها](ADMIN-ROUTING-FIX.md).
