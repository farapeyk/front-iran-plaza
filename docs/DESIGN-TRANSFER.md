# طراحی منتقل‌شده به Next

## هماهنگی با بک‌اند فعلی — ۲۰۲۶-۱۰-۱۳

قرارداد کامل از بک‌اند بازگردانی‌شده تولید شده است؛ هفت مسیر مقالات/تیکت و مسیر سوابق پرداخت حذف شده‌اند. کلاینت Orval از همین قرارداد بازتولید می‌شود و baseline نام‌ها و ۱۱۴ operation بک‌اند بدون تغییر است. صفحات مقالات، پشتیبانی و سوابق پرداخت اکنون وضعیت عدم دسترسی را نمایش می‌دهند و به endpoint حذف‌شده درخواست نمی‌زنند؛ جزئیات مقاله ۴۰۴ است. مقالات موقتاً noindex و خارج از sitemap هستند.

فیلتر VIP/رسانه در فهرست غیرفعال است، زیرا DTO بک‌اند فعلی این ورودی‌ها را نمی‌پذیرد. جستجو، شهر، محله، دسته و صفحه‌بندی به API موجود متصل‌اند. پروفایل عمومی از آدرس موجود استفاده می‌کند؛ نبود metadata اشتراک در این پاسخ به نشان VIP ساختگی تبدیل نمی‌شود. پلن‌های خرید با `tier=VIP` انتخاب می‌شوند؛ ثبت فاکتور از API موجود استفاده می‌کند و قیمت پلن را بک‌اند محاسبه می‌کند.

مولد قرارداد بک‌اند اکنون فیلدهای synthetic مدل‌های Prisma را نیز حفظ می‌کند؛ فیلدهای پایه پروفایل و دسته‌ها دوباره در قرارداد کامل هستند. این اصلاح endpoint یا migration جدیدی اضافه نمی‌کند. گزارش‌ها و لاگ‌های مدیریتی فقط شناسه، نام و تلفن کاربر مرتبط را دریافت می‌کنند و رمز/سهمیه BigInt را نمی‌خوانند.

audit فرانت با حذف `braces` و جایگزینی dependency محدود ابزار Next lint با `tinyglobby` به صفر رسید. تست سازگاری glob و lint واقعی حفظ شده‌اند. build داکر همچنان نیازمند فعال‌کردن محیط است؛ کاربر ابتدا آن را به بعد موکول کرد و سپس فقط این بررسی را برای commit/push همین نسخه روی main صریحاً معاف کرد. [گزارش QA](PUSH-QA.md) محدودیت و معافیت را ثبت می‌کند. اطلاعات تاریخی زیر، به‌تنهایی اثبات QA نسخه فعلی نیست.

## اصلاح مسیر کسب‌وکار فارسی — ۲۰۲۶-۱۰-۱۲

در مسیر `/businesses/نمایشگاه-ماشین-e823cb`، بک‌اند پاسخ ۲۰۰ داشت اما ورودی صفحه Next همچنان encoded بود؛ metadata ورودی decoded دریافت می‌کرد. encode دوباره در Orval باعث ۴۰۴ صفحه می‌شد. `businessSlugFromRoute` ورودی را دقیقاً یک بار decode و مسیرهای خراب یا دارای slash/control character را رد می‌کند؛ صفحه و metadata هر دو از آن استفاده می‌کنند. تست دائمی `tests/business-slug.test.cjs` برابری URL دو ورودی و جلوگیری از decode چندباره را بررسی می‌کند. درخواست HTTP واقعی پس از اصلاح ۲۰۰ و عنوان صحیح کسب‌وکار داشت. بک‌اند تغییر نکرد.

QA این اصلاح: `pnpm typecheck` و `pnpm lint` موفق؛ `pnpm test` شامل ۳۳ تست موفق است. Playwright/Edge روی همین بک‌اند در حال اجرا، در عرض‌های ۳۷۵ و ۱۴۴۰ پاسخ ۲۰۰، عنوان قابل مشاهده و نبود خطای JavaScript را تأیید کرد؛ تصاویر در `artifacts/business-slug-debug` workspace هستند. این بررسی فقط صفحه کسب‌وکار را پوشش می‌دهد و تأیید کل انتقال طراحی نیست.

`pnpm build` در snapshot مستقل فرانت موفق بود. `pnpm test:production` با سرور HTTP fixture نیز پاسخ ۲۰۰ برای slug فارسی، redirect نقش‌های مدیر و حفظ ۴۰۴ کسب‌وکار ناموجود را تأیید کرد. fixture این تست تولید دیتابیس واقعی نیست؛ بررسی مرورگر بالا از بک‌اند موجود واقعی استفاده کرد. هیچ تغییر تازه‌ای در بک‌اند ایجاد نشد.

**اصلاح دامنه ۲۰۲۶-۱۰-۱۲:** به درخواست کاربر، تغییرات بک‌اند این انتقال برگشت داده شد و ظاهر فرانت حفظ شد. اتصال صفحات و قرارداد تولیدشده در اصلاح ۲۰۲۶-۱۰-۱۳ بالا با API موجود هماهنگ شده است.

تمام فایل‌های صفحات، اجزا و داده‌های مرجع طراحی در `src/design` و assetهای آن در `public/design` هستند. صفحه‌های اصلی از نسخه‌های live با داده واقعی استفاده می‌کنند؛ داده نمایشی کتابخانه اجزا جای API اصلی نیست. ناوبری Next در `src/design/navigation.tsx` مسیرهای مرجع را به مسیرهای اصلی نگاشت می‌کند.

فونت‌های WOFF پیوست در `public/fonts/iransans` قرار دارند. `src/design/fonts.css` وزن‌های ایران‌سنس با ارقام فارسی را تعریف می‌کند؛ فونت و متغیرهای رنگ در `.plaza-design` محدودند. فایل‌های صفحات و اجزای ادمین تغییر نکرده‌اند.

## مسیرها

- عمومی: `/`، `/login`، `/categories`، `/businesses`، `/businesses/[slug]`، `/business-registration`، `/articles/`، URL ریشه‌ای مقاله `/<slug>/`، دسته‌های سلسله‌مراتبی `/category/.../`، `/about`، `/contact`، `/faq` و `/terms`.
- حساب: `/dashboard`، `/dashboard/profile`، `/dashboard/favorites`، `/dashboard/notifications`، `/dashboard/support`، `/dashboard/subscription` و `/dashboard/payments`.
- ثبت و ویرایش: مسیرهای موجود `/dashboard/business/new` و `/dashboard/business/profile/*` با اجزای طراحی و حفظ ذخیره مرحله‌ای؛ `/products/new` فرم ایجاد محصول واقعی است.
- لینک‌های طراحی `/profile`، `/user-info`، `/subscription`، `/payments` و `/support` به مسیرهای محافظت‌شده اصلی هدایت می‌شوند.
- `/design-system` و شش صفحه کتابخانه اجزا برای بررسی طراحی هستند؛ در production فقط با `DESIGN_REVIEW_ENABLED=true` در دسترس و همواره noindex هستند.
- `/payment-result` نتیجه verify واقعی سرویس پرداخت را نمایش می‌دهد.

## API و امنیت

`contracts/openapi.json` قرارداد کامل سرویس است. `orval.config.ts` کلاینت fetch مرورگر/سرور و مدل‌ها را تولید می‌کند. مرورگر فقط از BFF هم‌مبدأ `/api/backend` استفاده می‌کند؛ JWT در کوکی HttpOnly می‌ماند. client سرور از URL داخلی و نشست استفاده می‌کند. مسیرها encode و درخواست‌ها دارای timeout و پردازش خطای واقعی هستند.

BFF پس از refresh، GET را دوباره اجرا می‌کند؛ mutation ناموفق با 401 خودکار تکرار نمی‌شود تا عملیات دارای اثر جانبی دوبار انجام نشود. کاربر می‌تواند پس از تمدید نشست دوباره اقدام کند. مقصد پرداخت باید در `PAYMENT_ALLOWED_ORIGINS` مجاز باشد؛ origin لوکال فقط در development پذیرفته می‌شود.

کنترل مبدأ BFF و silent-refresh از origin معتبر `SITE_URL` استفاده می‌کند تا URL داخلی listener باعث رد فرم‌های واقعی نشود؛ مبدأ جعلی و درخواست cross-site رد می‌شوند. SITE_URL باید با آدرس مرورگر یکسان باشد. تصاویر marker نقشه از `public/leaflet/images` با مجوز Leaflet ارائه می‌شوند؛ کاشی‌های نقشه همچنان سرویس OpenStreetMap هستند.

مقالات و تیکت فعلاً سرویس فعال ندارند و فرم ارسال ارائه نمی‌شود. پرداخت با `FINANCE_ENABLED` بک‌اند کنترل می‌شود؛ خاموش بودن سرویس با حالت عدم دسترسی نمایش داده می‌شود. کمپین تبلیغاتی و ویس طبق دامنه مرحله‌ای قبلی به تعریف مستقل نیاز دارند؛ اجزای مرجع آن‌ها منتقل شده‌اند.

## اجرای بررسی

`pnpm exec orval` تولید کلاینت، `pnpm typecheck`، `pnpm lint`، `pnpm test` و `pnpm build` بررسی فرانت هستند. `pnpm exec playwright test` روی Next و بک‌اند مستقل بررسی لوکال، چهار عرض ۳۷۵، ۷۶۸، ۱۰۲۴ و ۱۴۴۰ را آزمایش می‌کند. تصاویر در `test-results/design-baseline` ذخیره می‌شوند؛ فایل‌های نتیجه و build نباید commit شوند.

فرمان‌های dev/build اکنون با Webpack اجرا می‌شوند؛ QA production هم روی همین mode است. `pnpm api:check` بازتولید دقیق کلاینت‌ها را کنترل می‌کند. تنظیم encode مسیر در سطح output طبق [مستندات Orval](https://orval.dev/docs/reference/configuration/output/) است. FAQ و لینک پشتیبانی فعال جای متن و شماره نمونه را گرفته‌اند؛ آیکن شبکه اجتماعی فاقد URL تنظیم‌شده لینک فعال نیست.

پیش‌نمایش workspace روی `http://127.0.0.1:3001` و بک‌اند بررسی روی `3100` اجرا می‌شود. PostgreSQL مستقل واقعی است؛ Redis، پیامک و پرداخت mock هستند. شماره مشتری `09120000001` است؛ کد mock فقط در development پس از درخواست نمایش داده می‌شود. این داده و پیکربندی برای تولید نیست.
