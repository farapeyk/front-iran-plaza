# کش داشبورد مشتری

## رفتار

داشبورد مشتری برای سه فهرست «کسب‌وکارها»، «کسب‌وکارهای ویژه» و «علاقه‌مندی‌های من» پاسخ API را در `sessionStorage` مرورگر نگه می‌دارد. در بازدید دوباره، داده‌ی معتبر همان کاربر پیش از پاسخ شبکه نمایش داده می‌شود و درخواست‌ها هم‌زمان در پس‌زمینه اجرا می‌شوند تا داده تازه شود.

کش عمومی پنج دقیقه و کش علاقه‌مندی‌ها یک دقیقه اعتبار دارد. کلیدها شامل شناسه کاربر و نسخه کش هستند؛ در نتیجه کش دو حساب با هم ترکیب نمی‌شود. علاقه‌مندی‌ها بعد از انقضا از API خوانده می‌شوند. مرورگر منبع دائمی داده نیست و خطای دسترسی یا پر بودن storage مسیر نمایش/API را از کار نمی‌اندازد. اطلاعات اعتبارنامه در این کش ذخیره نمی‌شود.

این تغییر فقط داشبورد مشتری را پوشش می‌دهد؛ صفحه‌های مستقل پروفایل، اعلان‌ها و علاقه‌مندی‌ها فعلاً سروررندر و جدا از این کش هستند. برای کنترل تازگی داده، داشبورد با هر mount داده‌ها را دوباره از API می‌گیرد.

## QA و استقرار

تست‌های `tests/customer-dashboard-cache.test.cjs` جداسازی بر اساس کاربر، اعتبار زمانی، داده خراب و در دسترس نبودن storage را بررسی می‌کنند. این تست‌ها با storage ساختگی اجرا می‌شوند و آزمون مرورگر واقعی محسوب نمی‌شوند.

تغییر runtime در push شاخه `main`، workflow `.github/workflows/production.yml` را اجرا می‌کند. workflow تست‌ها و build را انجام می‌دهد و سپس به‌ترتیب منطقه ایران و خارجی را deploy می‌کند. وضعیت نهایی اجرای GitHub Actions و سلامت production پس از push باید به این سند افزوده شود.
