# هدایت مدیر به پنل اصلی

تاریخ: ۲۰۲۶-۱۰-۰۷. این اصلاح ادامه بررسی فرانت است؛ گزارش‌های QA قبلی سابقه‌اند.

## رفتار

- ورود موفق OTP برای `ADMIN` و `SUPER_ADMIN` مستقیم به `/admin` می‌رود، حتی با حساب تازه یا نام ناقص. ورود با رمز مدیر همین مقصد را دارد.
- JWT معتبر مدیر روی داشبورد کاربران، تمام زیرمسیرهای آن، تکمیل پروفایل و صفحات ورود، پاسخ redirect ۳۰۷ به پنل اصلی می‌گیرد. پنل مدیر خودش redirect نمی‌شود؛ مسیرهای مشابه مانند `/dashboardish` مشمول محافظ داشبورد نیستند.
- هدرهای عمومی و منوی موبایل لینک حساب مدیر را به پنل اصلی و ثبت کسب‌وکار را به ثبت دستی مدیر متصل می‌کنند.
- نقش‌های غیرمدیر رفتار حساب عادی را حفظ می‌کنند و اجازه ورود به پنل مدیر ندارند. صفحات عمومی قابل مرور هستند.
- توکن نامعتبر روی صفحه محافظت‌شده ابتدا به silent-refresh می‌رود؛ پس از تمدید نقش دوباره بررسی می‌شود. صفحات ورود برای نشست فاقد access token معتبر باز می‌مانند.

## فایل‌ها و بررسی

تابع مشترک نقش در `src/lib/auth/roles.ts`، محافظ `src/proxy.ts`، actionهای OTP و رمز، هدر خانه، هدر عمومی و منوی موبایل تغییر کرده‌اند. `tests/admin-routing.test.cjs` تست مقصد ورود با نقش‌های مدیر/کاربر و حساب کامل/ناقص، کنترل cookie پس از ورود با رمز و HTML لینک‌های دسکتاپ/موبایل را اضافه می‌کند. آزمون production موجود نیز HTTP واقعی redirect هر دو نقش مدیر روی پنج مسیر را بررسی می‌کند. هیچ endpoint، قرارداد API یا schema دیتابیس تغییر نکرده است.

## QA این اصلاح

| فرمان / بررسی | نتیجه نهایی |
| --- | --- |
| `npm run lint` | موفق، بدون warning |
| `npm run typecheck` | موفق |
| `npm test` | ۲۶ تست موفق |
| `npm run build` | موفق؛ ۳۷ صفحه تولید شد |
| `npm run test:production` | موفق؛ ۱۰ درخواست HTTP برای دو نقش روی پنج مسیر به `/admin` هدایت شدند؛ regression جزئیات کسب‌وکار نیز موفق بود |
| تست مستندات | لینک‌های محلی، UTF-8، fence و فهرست کامل سورس بررسی شدند |
| `git diff --no-index --check` با پشتیبان | بدون خطای whitespace در سورس، تست و مستندات؛ exit برابر ۱ ناشی از تفاوت فایل‌هاست |

تست production ابتدا به‌دلیل نسبی‌بودن header استاندارد `Location: /admin` در Next شکست خورد؛ انتظار تست با resolve کردن URL نسبت به origin اصلاح شد و اجرای نهایی موفق بود. فهرست سورس نیز برای فایل‌های تازه به‌روز شد و تست کامل دوباره اجرا شد.

تست action و HTML از mock استفاده می‌کنند. تست production از Next واقعی و بک‌اند fixture ایزوله با کلید آزمایشی استفاده می‌کند؛ ورود با حساب واقعی، بک‌اند واقعی و تعامل مرورگر در این QA اجرا نشده‌اند. workspace مخزن Git ندارد؛ بررسی staged و commit قابل اجرا نیست و commit انجام نشده است.
