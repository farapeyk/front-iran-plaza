# اصلاح جزئیات کسب‌وکار مدیر

تاریخ: ۲۰۲۶-۱۰-۰۷. مسیر گزارش‌شده: `/admin/businesses/cmsfz4qtl00027msz3yr5z4nl`.

## علت رگرسیون

در اصلاح قبلی، `getPlans` از `pageFetch` استفاده می‌کرد. این helper با هر پاسخ ۴۰۴، `notFound()` را اجرا می‌کند. چون اطلاعات اصلی و پلن‌ها با Promise.all دریافت می‌شدند، ۴۰۴ پلن‌ها صفحه کسب‌وکار موجود را نیز به صفحه عمومی «پیدا نشد» تبدیل می‌کرد. این تغییر قبلی فرانت باعث رگرسیون شد.

در بررسی HTTP تازه، `/api/plans` واقعاً ۴۰۴ و `/docs-json` برابر ۲۰۰ بود. درخواست بدون نشست به اطلاعات کسب‌وکار ۴۰۱ داد؛ نبود دسترسی در این درخواست، شاهد حذف رکورد نیست. داده واقعی این کسب‌وکار بدون نشست مدیر خوانده نشده است.

## رفتار اصلاح‌شده

- دریافت اطلاعات اصلی از خطاهای جانبی جدا شده است؛ فقط ۴۰۴ خود کسب‌وکار به notFound می‌رود.
- خطای پلن‌ها با پیام مشخص داخل کنترل پلن نمایش داده می‌شود؛ اعطای پلن غیرفعال است، ولی مشخصات و سایر بخش‌ها باقی می‌مانند.
- درخواست پلن‌ها نیز نشست جاری را در Authorization دارد.
- مدارک و مجموعه‌های پروفایل، در صورت نبودن در پاسخ اصلی، از endpointهای جدا دریافت می‌شوند؛ اطلاعات اصلی API زنده همه مجموعه‌ها را در schema خود ندارد.
- امکانات، آدرس/نقشه و شعب، گالری، ویدیو/صوت، تماس و شبکه اجتماعی، درباره ما، خدمات، محصولات و دسته‌های آن‌ها، ساعات و اقساط در نمای مدیر نمایش داده می‌شوند.
- این نما برای وضعیت PENDING نیز از endpointهای جزئیات استفاده می‌کند؛ برای خواندن اطلاعات مدیر به پروفایل عمومیِ فقط APPROVED وابسته نیست.
- قطع سرویس یا ۴۰۴ بخش جانبی، فقط همان بخش را با پیام مشخص علامت می‌زند؛ ۴۰۱/۴۰۳ مدارک و بخش‌های خصوصی پنهان‌سازی نمی‌شوند و خطای دسترسی باقی می‌ماند.
- داده‌های پولی رشته‌ای Decimal با Number برای نمایش فارسی قالب‌بندی می‌شوند. محتوای متنی با React escape می‌شود؛ HTML ذخیره‌شده به شکل خام اجرا نمی‌شود.

## اعتبار QA

تست‌های regression از داده آزمایشی استفاده می‌کنند. آزمون production، Next واقعی و HTTP واقعی روی loopback را با secret و backend fixture مستقل اجرا می‌کند؛ هیچ نشست مدیر جعلی به بک‌اند واقعی ارسال نمی‌شود. این آزمون برابر تست مرورگری یا تأیید محتوای واقعی حساب مدیر نیست.

| فرمان / بررسی نهایی | نتیجه |
| --- | --- |
| `npm run lint` | موفق؛ صفر error و warning |
| `npm run typecheck` | موفق |
| `npm test` | موفق؛ ۲۳ تست، شامل چهار regression جدید |
| `npm run build` | موفق؛ route جزئیات مدیر در خروجی موجود است |
| `npm run test:production` | موفق؛ کسب‌وکار PENDING با پلن ۴۰۴، HTTP ۲۰۰ و heading/بخش‌های اطلاعاتی دارد؛ کسب‌وکار ناموجود HTTP ۴۰۴ می‌دهد. |
| کنترل no-index whitespace در src/tests/docs در برابر پشتیبان | بدون تشخیص خطای whitespace؛ exit=1 مربوط به تفاوت فایل‌هاست و staged check نیست. |

در آزمون production، heading رندرشده بررسی می‌شود؛ متن fallback ۴۰۴ که Next در RSC serialize می‌کند به‌تنهایی به معنی نمایش صفحه ۴۰۴ نیست. سرورهای fixture و Next پس از آزمون بسته می‌شوند. UI با نشست واقعی مدیر و تصاویر واقعی به‌صورت مرورگری تست نشده است.

فرمان اجرای آزمون integration پس از build:

```powershell
npm run build
npm run test:production
```

Git repository در پوشه موجود نیست؛ commit انجام نشده است. بک‌اند و دیتابیس تغییر نکرده‌اند و endpoint یا قرارداد سرور در این اصلاح ایجاد/بازنویسی نشده است.
